Because college alone isn't enough.

We need to experience **real problems with real deadlines**.

Hackathons force us to:

* Think under pressure
* Work as a team
* Divide responsibilities

* Learn unfamiliar technologies

# 🧠 Our Learning Philosophy

We follow one simple rule:

> **Don't try to know everything. Learn what you need, build with it, and understand what you build.**

We will use:

* Documentation
* YouTube
* Courses
* GitHub
* AI tools
* Open-source projects
* Community knowledge
* Our own experimentation

AI is allowed.

But **blindly copying AI-generated code is not our goal.**

If AI writes something for us, we should eventually understand:

```text
What does this code do?
Why does it work?
How does it connect to our project?
How can we modify it?
What happens if it breaks?
```

# 🔀 Our Development Workflow

Every project should roughly follow this process:

### 1️⃣ Understand

What problem are we solving?

### 2️⃣ Research

Who has this problem?

What solutions already exist?

### 3️⃣ Ideate

Can we create something better, simpler, cheaper, faster, or more useful?

### 4️⃣ Design

Create the basic UI/UX and system architecture.

### 5️⃣ Build

Start developing the MVP.

### 6️⃣ Integrate

Connect frontend, backend, database and APIs.

### 7️⃣ Test

Find bugs and fix critical issues.

### 8️⃣ Deploy

Put the project somewhere people can actually use it.

### 9️⃣ Present

Explain:

```text
Problem
↓
Solution
↓
Technology
↓
Innovation
↓
Impact
↓
Demo
```

# 🧪 Our MVP Rule

During a hackathon:

> **A working simple product is more valuable than an unfinished complicated product.**

We will first build:

```text
MVP
↓
Working Features
↓
Testing
↓
Polish
↓
Extra Features
```

Instead of:

```text
50 Features
↓
Nothing Works
```

# 📈 Our Progress System

After every hackathon, we will conduct a team review.

### Questions:

* What did we build?
* What worked?
* What failed?
* What technology did we learn?
* Where did we waste time?
* What technical mistakes did we make?
* What teamwork problems occurred?
* Was our presentation clear?
* What should we improve before the next competition?

We don't consider a hackathon a failure just because we don't win.

**Every competition should leave us stronger than before.**

# 🔥 Team Rules

### Rule 1 — Show up

Consistency beats motivation.

### Rule 2 — Learn before complaining

If something doesn't work:

```text
Understand the error
↓
Search
↓
Try
↓
Ask
↓
Fix
```

### Rule 3 — Don't hide problems

If you're stuck, tell the team.

A problem discovered early is easier to solve.

### Rule 4 — Respect everyone's role

Frontend, backend, design, research and presentation are all important.

### Rule 5 — Share knowledge

If one person learns something useful, teach the others.

### Rule 6 — Commit your work

Use Git and GitHub properly.

### Rule 7 — Don't fake understanding

If you don't understand something, say:

> "I don't understand this yet."

Then learn it.

### Rule 8 — Build more than you watch

```text
20% Learning
80% Building
```

The exact ratio can change, but practice must remain a major part of our learning.
